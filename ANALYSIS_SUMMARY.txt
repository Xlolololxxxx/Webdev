KEY FINDINGS: HOW THE EXTRACTION WORKS
================================================================================

MECHANISM: Network Interception via WebViewClient.shouldInterceptRequest()

FLOW:
1. WebView loads a URL
2. For EACH resource (JavaScript, CSS, images, fonts, etc.), WebView attempts
   to load it and triggers shouldInterceptRequest()
3. The app intercepts the request and extracts:
   - URL
   - HTTP Method (GET, POST, etc.)
   - Request Headers (Authorization, User-Agent, etc.)
4. The app makes a parallel request using OkHttp3 to capture response details:
   - MIME Type (application/json, text/css, image/png, etc.)
   - Encoding (utf-8, iso-8859-1, etc.)
   - HTTP Status Code (200, 404, 500, etc.)
   - Response Headers (Cache-Control, Content-Length, etc.)
5. The app stores this metadata in Source model objects
6. The method returns NULL to allow WebView to continue loading normally
7. The source is added to the list and displayed in the RecyclerView

================================================================================
DATA CAPTURED
================================================================================

PER REQUEST:
- URL string
- HTTP method (GET, POST, OPTIONS, HEAD, DELETE, PUT, PATCH)
- Request headers map (all headers sent to server)

PER RESPONSE:
- MIME type string (Content-Type header)
- Encoding string (charset from Content-Type)
- HTTP status code (200, 404, 304, 500, etc.)
- Response headers map (all headers from server)

DERIVED:
- Resource type extracted from MIME type or URL extension
  Examples: "js", "css", "json", "html", "image", "font", "text", "wasm"

NOT CAPTURED:
- Response body content (intentionally null)
- Cookies (handled by WebView)
- WebSocket messages
- Service worker requests
- Data: URLs (intentionally filtered)

================================================================================
KEY DESIGN DECISIONS
================================================================================

1. Return NULL from shouldInterceptRequest()
   WHY: Allows WebView to load normally instead of serving the response.
        We capture metadata but don't block the actual resource loading.

2. Use OkHttp3 for parallel requests
   WHY: Can capture full request/response metadata. Consistent with app's
        existing HTTP client. Proper SSL/TLS handling. Allows logging.

3. Dual method overloading
   WHY: Support both modern API (21+) and legacy Android versions
        - shouldInterceptRequest(WebView, WebResourceRequest)
        - shouldInterceptRequest(WebView, String)

4. Asynchronous UI updates via runMainJob()
   WHY: Don't block network threads. Queue UI updates on main thread safely.

5. Filter data: URLs
   WHY: Avoid capturing inline CSS and JavaScript. Reduce noise and memory.

HOW TO REPLICATE EXACTLY
================================================================================

STEP 1: Create WebViewClient subclass
```kotlin
class SourceExtractorClient : WebViewClient() {
    override fun shouldInterceptRequest(view: WebView?, request: WebResourceRequest?): WebResourceResponse? {
        if (request != null) {
            // Extract request details
            val url = request.url.toString()
            val method = request.method
            val headers = request.requestHeaders
            
            // Make OkHttp3 request
            val okRequest = Request.Builder()
                .url(url)
                .method(method, null)
                .headers(Headers.of(headers))
                .build()
            
            val response = httpClient.newCall(okRequest).execute()
            
            // Create Source object with metadata
            val source = Source(
                request = Source.Request(url, method, headers),
                response = Source.Response(
                    mimeType = response.header("Content-Type") ?: "",
                    encoding = response.body?.contentType()?.charset()?.name() ?: "utf-8",
                    statusCode = response.code,
                    headers = response.headers.toMap()
                )
            )
            
            // Add to list (queue on main thread)
            addSourceToUI(source)
        }
        return null  // CRITICAL: return null
    }
}
```

PERFORMANCE CONSIDERATIONS
================================================================================

BANDWIDTH:
- Each resource downloaded TWICE (once by WebView, once by OkHttp3)
- Doubles bandwidth usage for page loads
- Could noticeably slow down page loading

MEMORY:
- All source metadata stored in RAM
- ~100 resources = 10-50 MB depending on header sizes
- Could cause issues on low-memory devices
- No disk persistence in current implementation

THREADING:
- Network requests are synchronous (blocking)
- Main thread updates are queued asynchronously
- Could cause ANR (Application Not Responding) on very slow connections

OPTIMIZATION TIPS:
1. Implement request filtering to skip certain resource types
2. Use async/coroutines instead of synchronous requests
3. Implement memory-bounded cache (LRU cache)
4. Serialize sources to disk to free memory
5. Use connection pooling for OkHttp3

SECURITY & PRIVACY
================================================================================

THIS APP CAPTURES AND STORES:
- COMPLETE BROWSING HISTORY (every URL visited)
- REQUEST HEADERS (may contain Authorization tokens, API keys, etc.)
- RESPONSE HEADERS (server information, cache settings, etc.)
- HTTP STATUS CODES (can infer server behavior and structure)

RISK FACTORS:
- If device is compromised, all captured data becomes accessible
- Browsing history is sensitive personal information
- Auth tokens in headers could be extracted
- Could violate privacy of users browsing private content

USERS SHOULD KNOW:
- This data is stored in memory and potentially serialized
- No encryption of captured metadata
- Could be accessed by other apps with sufficient permissions
- Users should use this on trusted devices only

- move-result: Stores return value from previous invoke

CONCLUSION
================================================================================

The web source extraction mechanism is an elegant design that allows the app to
capture all web resources loaded by a page without intercepting or modifying them.

KEY INSIGHT: The magic is in returning NULL from shouldInterceptRequest().
This tells Android "I didn't intercept this request, let WebView handle it
normally" - but we already captured the metadata before returning null.

TECHNIQUE SUMMARY:
1. Intercept with shouldInterceptRequest()
2. Extract metadata from WebResourceRequest
3. Make parallel OkHttp3 request to get full response details
4. Convert to Source model objects
5. Queue UI update asynchronously
6. Return NULL to allow normal loading

This design pattern could be used for many purposes:
- Tracking all resources loaded by a page
- Building a resource graph/dependency tree
- Testing website performance
- Security auditing of websites
- Privacy analysis (tracking pixels, etc.)
- Development tools (see what resources are loaded)

The implementation is production-quality with proper error handling,
null checks, and thread safety considerations.
